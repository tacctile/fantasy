## Build — line 80 → [x]

**Shared layer (`services/dashboard.ts`)** — `SectionOutcome<T>` (`ok`/`unavailable`), `settleQuery(label, query, fallback)` (catches THROWN failures only, logs `[dashboard] <label> failed` server-side, returns the fallback; typed not-found/invalid results pass through untouched because they are answers, not failures), `toSection(result)`, `firstContext(sections)`, `SECTION_UNAVAILABLE`. Deliberately one concept shared by both surfaces rather than two parallel inventions — data-access sharing is sanctioned; only UI is not.

**Admin** — `league-dashboard-shell.tsx` and `command-center.tsx` now take an explicit `context` plus one `SectionOutcome` per section; new `components/dashboard/section-unavailable.tsx` renders the failure notice. Both admin pages settle every query (standings, power, matchups, player card, scored weeks, share token). 404 is reserved for a genuinely not-found league; the route error boundary is reached only when *every* section failed (no league identity left to render a header with) — that case throws deliberately rather than rendering a nameless shell of notices. The player sheet gained an `unavailable` branch distinct from `player_not_found`.

**Spectator** — `resolveSpectatorLeague` now selects the league's identity columns, so the header survives any section failing (previously the context was lifted out of the standings result, which made standings a single point of failure for the whole page). `loadSpectatorDashboard` settles each section; `matchups` is `{status:'ok', data:null}` for "nothing scored yet" versus `unavailable` for a failed query — conflating those would tell a viewer the league has no games when the database is simply down. New `spectator-section-notice.tsx` (inline) and `spectator-unavailable.tsx` (whole page), both spectator-local by the separate-rendering-path rule, with viewer-appropriate copy (no sync to run, no logs to read).

**The two missing route files** — `share/[share_token]/loading.tsx` (mobile-first skeleton mirroring SpectatorShell, smaller row counts than the admin skeleton on purpose) and `share/[share_token]/error.tsx` (the segment's one client module — Next requires an error boundary to be a Client Component). Judgment call, disclosed: the *normal* failure path never reaches `error.tsx`, because `page.tsx` catches loader throws itself (`settleLoad`) and renders the static unavailable view server-side; the boundary covers render/hydration throws only. That is what keeps Nick's "no button, no client JS" choice true on the failure path while still closing the STATE.yml known issue (a genuine DB error previously fell through to Next's default error page).

**Copy discipline** — every failure string is visibly different from its section's empty string, and none carries error content, a digest, or a league name on the spectator side.
