## Item 1 — chart colour-scale tokens

Clarify (4 questions, all answered with the recommended option):
1. **Teal collision** → categorical ramp deliberately clear of the teal hue band; `--chart-1` re-pointed off `--primary`. Grepped first: **zero consumers** of any chart token in `src/`, so the re-point had no call sites to migrate.
2. **Positional accents** → reuse the six `--pos-*` tokens and widen their documented usage rule from "badges/chips only" to "badges, chips, and positional chart marks"; the never-a-row-tint half unchanged.
3. **Divergence** → mint `--chart-positive`/`--chart-negative` aliasing `--positive`/`--destructive`, so a future chart re-tune can move without dragging win/loss/injury semantics.
4. **Heatmap ramp** → diverging at league average (percentile-vs-league is inherently a divergence, and it makes "weak at WR" jump out — which is the cross-feature link the build file wants).

**Colour was computed, not eyeballed.** Loaded the `dataviz` skill (its trigger is explicit for chart colour work), wrote an oklch→sRGB converter, and ran its `validate_palette.js` six-checks validator against the real surfaces.
- First candidate ramp (blue 250 / orange 45 / purple 300 / green 140 / magenta 330) passed all six on the **adjacent** pairlist against both `--card` and `--background`: worst adjacent CVD ΔE 18.6 deutan / 14.6 tritan, normal-vision 28.9, contrast ≥ 3:1 on all five.
- It **failed `--pairs all`**, as the skill itself predicts for any 5-slot ramp (green↔orange collapse under deuteranopia at ΔE 2.8 is fundamental, not fixable by re-ordering). Attempted a re-hued/re-lightened alternative to clear all-pairs at 4 slots; it made things **worse** (dropped two slots below 3:1 contrast and pushed orange out of the lightness band). Reverted.
- **Resolution, recorded as the design decision rather than a workaround:** the all-pairs pairlist is required for scatter/bubble/choropleth/small-multiples. Of those only small multiples is in this wave, and the small-multiples primitive was then built **monochrome by design** — one slot-1 colour per facet, identity carried by the facet title. That structurally removes every all-pairs form from the wave, leaving the categorical ramp serving only adjacent-pairlist forms (grouped bars, ≤4 overlaid lines), where it passes cleanly. Better design independently: facet titles already carry identity, so spending a colour slot per facet encodes nothing new.
- Compiled CSS confirmed the shipped values are the validated ones (`--chart-1:#2389e2`, `--chart-neutral:#6f7179`) and that `bg-chart-grid{background-color:var(--chart-grid)}` actually resolves rather than silently no-op'ing.

Also minted `--chart-grid` (6%, deliberately *below* `--border`'s 10% so furniture never competes with a mark) and `--chart-axis` (18%), with `@theme inline` mappings for all five new tokens.

## Item 2 — shared chart-primitives layer

Clarify (3 questions, all answered with the recommended option). Two facts found while scoping made these real rather than formal: `components/spectator/` imports **only types and `cn`** today (grepped), and the surface's zero-client-JS guarantee is enforced by a **passing test**, so it can't be quietly traded away.
1. **Library → none, hand-rolled.** Decisive reason is not dependency count: a measurement-based responsive container (Recharts' `ResponsiveContainer`) forces `'use client'`, which the spectator surface cannot accept. Percentage-positioned marks are correct at any width with zero JS.
2. **`components/charts/` shared by both surfaces** — the first exemption to the separate-rendering-path rule, on the ground that a token-driven geometry primitive carries no admin markup, data, or affordance. Spectator FEATURE components stay local copies.
3. **Admin hovers, spectator direct-labels** — the sanctioned relief channel, and a phone has no hover anyway.

Consequential design call made while building: the hover layer is a **pure CSS** `group-hover`/`group-focus-within` opacity transition, so even admin chart sections stay RSC with no client module at all — stronger than what the Clarify answer required. `tabIndex` + `sr-only` label make the values keyboard- and screen-reader-reachable rather than mouse-only.

Shipped 9 files under `src/components/charts/`: `scales.ts`, `series.ts`, `format.ts`, `chart-frame.tsx`, `value-axis.tsx`, `category-axis.tsx`, `chart-legend.tsx`, `chart-mark.tsx`, `chart-skeleton.tsx`, `chart-empty.tsx`. Notable encoded decisions: `divergingBar` scales both arms against one shared magnitude (so +2 and −2 render equal) and treats exact zero as its own `'zero'` reading; `polylinePoints` **breaks** the line at a non-finite week rather than interpolating across a week that was never scored; `positionOf` clamps so an anomalous score can't escape the plot; `seriesVar` returns **null** past slot 5 rather than cycling two teams onto one colour; `chart-frame` applies `tabular-nums` once so every tick/tooltip/legend value inherits it (the build file's requirement, enforced structurally); skeleton bar heights are a fixed cycle, not random, because a reshuffling skeleton reads as content loading twice; empty copy is kept deliberately distinct from failure copy, per the Wave 4 resilience rule.

No `index.ts` barrel created — `find src -name index.ts` returns nothing, and the convention forbids adding barrels where none exist.

Caught and fixed during the item: an arbitrary `text-[0.6875rem]` in the axis labels, replaced with `text-xs` (Tailwind default scale only).

## Item 3 — small-multiples layout primitive

Clarify (2 questions, both answered with the recommended option): **one shared domain across every facet, no per-facet opt-out** (per-facet scaling would render a 70-point team's chart identically to a 140-point team's and silently invalidate the comparison the grid exists to make — a low-scoring facet looking flat IS the honest reading); and **title + one shared scale caption**, not 12 repeated axes (DESIGN_SYSTEM's annotation-light direction and its named legacy-fantasy-clutter anti-reference). The primitive never sorts — the caller's ordering stays authoritative — and facets are monochrome, which is also what discharges the all-pairs colour constraint from item 1.
