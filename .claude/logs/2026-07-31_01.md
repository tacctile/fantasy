## Item-by-item

### Line 72 — the spectator route → [x]

`app/share/[share_token]/page.tsx`, deliberately **outside** the `(admin)` route group (so it never inherits the owner auth gate) and outside `proxy.ts`'s `/leagues` redirect (so an anonymous viewer is never bounced to `/login`). Data comes only from `loadSpectatorDashboard`/`loadSpectatorPlayerCard`; the route's import graph reaches `lib/supabase/spectator.ts` and neither `server.ts` nor `admin.ts` — asserted, not assumed (see the test).

`?week=` is not read at all (Clarify 2). `?player=` is read and opens the drawer. Invalid/revoked/blank token → `notFound()` → the segment's `not-found.tsx`: a real 404 that names no league, owner, or team (an invalid token must not confirm or deny what it used to open) and offers no login/signup affordance, because viewers never have accounts. Static `metadata` carries the robots directive; deliberately static rather than `generateMetadata`, which would cost a second token resolution per request for a browser-tab string.

### Lines 73–77 — the five components → [x]

All under `components/spectator/`, importing **zero** components from `components/dashboard`, `components/draft-board`, or `components/auth`. Every navigation is a plain `<a>`, not `next/link` — the spectator surface ships with no client-side JS at all, which is both the right call for a phone on league-day cell service and what makes the whole composition renderable in a plain node test.

- `spectator-standings.tsx` — stacked rows, PF only.
- `spectator-matchups.tsx` / `spectator-matchup-card.tsx` — current week, stacked; mirrored headers with totals on the outer edges, starters mirrored beneath with points toward the **center gutter** (deliberately unlike the admin card's outer rails: on a narrow screen adjacent score columns make the head-to-head comparison, and outer-edge names absorb the truncation). Bench omitted. Single-side cards render byes and the service's anomaly fallout honestly; the anomaly *flag* itself is not surfaced — that is admin diagnostic noise — but no row is ever silently dropped or force-paired.
- `spectator-power-rankings.tsx` — rank/team/delta, plus the two caveats the wiki mandates.
- `spectator-player-card.tsx` + `spectator-player-drawer.tsx` — bottom drawer (mobile thumb reach) rather than the admin's right-edge sheet; anchor dismissal; `not_rostered` FA-gap weeks stay honest.
- `spectator-unofficial-chip.tsx` / `spectator-as-of-time.tsx` — spectator-**local** copies of the freshness pair. Disclosed judgment call: this is deliberate duplication. The Access Model's separate-rendering-path rule is a data-exposure boundary, and importing two admin components across it to save ~30 lines would weaken the one property the import-graph test exists to guarantee. The rule they implement (a non-final or stale score is never silently presented as current) is project-wide and unchanged.
- `spectator-shell.tsx` — the composition. Takes an optional `playerSlot` so it stays a pure synchronous component: the async token work lives in the page, which is what makes the whole response renderable in the boundary test without a database.

### Line 81 — the no-admin-markup test → [x]

`components/spectator/spectator-markup.test.ts`, 30 tests, **two complementary guards** because either alone is escapable:

1. **Rendered output** — the composed response (shell + open player drawer) through `renderToStaticMarkup`, asserted free of every admin nav label, draft/BPA vocabulary, `/leagues/` and `/login` links, and — the strongest single assertion — any `<button>`, `<form>`, or `<input>` at all. The regenerate-token control is a button, so its absence is asserted *structurally* rather than by name, which survives someone renaming the button.
2. **Import graph** — a transitive walk from the route entry resolving `@/` and relative specifiers, asserting zero `components/dashboard|draft-board|auth` imports, zero draft services, and that neither the owner nor the service-role Supabase factory is reachable. This catches an admin component pulled in behind a branch the fixture never renders, which a snapshot fundamentally cannot.

The graph test also asserts positively (it *does* reach `spectator-shell.tsx`, `services/spectator.ts`, `services/dashboard.ts`, `lib/supabase/spectator.ts`), so a broken walker fails loudly instead of passing vacuously on an empty set.

One lint suppression, documented in place: `react/no-children-prop` on the one `createElement` call. The vitest `include` glob is `*.test.ts`, so there is no JSX available, and `createElement`'s typed overload requires `children` inside props when the component declares it required — children-as-prop is forced by the file type, not chosen.
